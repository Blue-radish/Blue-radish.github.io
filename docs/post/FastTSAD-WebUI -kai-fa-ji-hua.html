FastTSAD-WebUI 开发计划

一、项目背景

FastTSAD 是一个时序异常检测基准框架，内置多种算法、统一数据管线与评估指标（Affiliation / VUS / R-AUC），但目前只有命令行接口，使用门槛较高。

本项目为其构建 Web 可视化系统，目标：用户通过浏览器即可完成数据集管理、模型训练（含过程可视化）、模型管理、模型测试（含结果可视化）。

技术选型

层 选型 理由
前端 Vue 3 + Vite + Element Plus + ECharts 组件齐全；ECharts 支撑大时序图缩放/平移
后端 Python FastAPI FastTSAD 是 Python，可同进程 import；单运行时
存储 SQLite + 文件系统 零安装零配置，下载即用
部署 单进程 python app.py 一条命令启动，无需 MySQL / Java 环境

二、当前进度（截至 2026-09-11）

FastTSAD 侧的 API 改造已完成，提交至 sglu 分支并推送：

改动 说明
训练进度回调 BaseSolver._emit_epoch()，14 个算法全部接入，CLI 行为不变
结构化评估返回 evaluate() 返回异常分数、真值、预测、全套指标
阈值捕获机制 metrics/capture.py thread-local 捕获，支撑前端切换阈值档位
Bug 修复 KANAD 缺失 return、PaAno 未注册、BeatGAN 回调缺失、anormly 拼写

三、Plan

9/18

主题：骨架就位 + 可浏览的 WebUI

交付物

  1. 阶段一验证收尾：真实数据跑通 evaluate()，确认异常分数、指标、阈值扫描可用
  2. WebUI 工程骨架：仓库初始化、依赖、目录结构、启动脚本、Git 接入
  3. 前端骨架：Vite + Element Plus + 路由 + 响应式侧边栏（桌面固定 / 手机抽屉）
  4. 三个可浏览页面：首页、数据集、FastTSAD 算法库
    • 首页：框架简介 + 统计概览
    • 数据集：搜索框 + 分页列表（名称 / 描述 / 通道数 / 创建时间）
    • 算法库：卡片网格（简介 / 论文链接 / 使用入口）+ 导入新算法交互
  5. 后端最小闭环：数据集注册表 + 算法扫描器 + 上述页面的 REST API

核对点

  • FastTSAD API 改造是否满足后续需求？evaluate() 返回结构是否需要调整？
  • 数据集元数据（名称 / 描述 / 通道数）取值范围是否合理？描述文案是否需要补充？
  • 算法库页面信息（简介 / 论文链接 / 使用入口）是否足够？
  • "导入新算法"交互方案（引导放入 methods/ + 刷新重扫）是否认可？
  • 页面视觉风格与信息密度是否符合预期？整体技术路线是否认可？

演示内容

浏览器打开 WebUI → 首页 → 数据集页（搜索、分页）→ 算法库页（卡片网格、论文链接、导入引导）

9/25

主题：训练闭环打通

交付物

  1. 后端任务系统：训练任务队列、串行调度、进度采集、取消 / 删除
  2. SQLite 完整表设计：数据集、算法、模型、训练任务、训练指标、检测任务
  3. 我的训练页
    • 基础模型 / 数据集 / 模型名称选择
    • 超参数动态表单：按所选算法自动渲染其专属超参，默认值取自框架
    • 历史任务列表（分页、以训练轮数驱动的进度条、取消 / 删除）
  4. 训练过程可视化：Loss 曲线 + 验证集指标曲线
  5. 我的模型页（基础版）：分页列表、模型名查询、单个 / 批量删除（含确认弹窗）
  6. 模型仓库管理：训练产物落盘、模型注册表、模型与训练任务的关联

核对点

  • 超参数表单的呈现方式（分组、默认值来源）是否合理？
  • 训练进度与曲线的展示粒度（每轮一个点）是否够用？
  • 任务队列的串行策略（同时只跑一个训练）是否可接受？
  • 模型列表字段（基础模型 / 通道数 / 数据集 / 创建时间）是否够用？
  • 训练中断 / 失败的处理方式是否符合预期？

演示内容

新建训练任务 → 实时进度条 + Loss 曲线 → 训练完成 → "我的模型"查看模型、启用

10/2

主题：Lab 全流程 + 交付

交付物

  1. 我的模型页（完整版）：查看训练时的 Loss / 指标曲线、使用（跳转 Lab）
  2. Lab 页
    • 模型 + 数据集选择，通道数不匹配预警（橙色提示 + 确认弹窗）
    • 检测任务历史（分页）
  3. 结果可视化页（核心）
    • 全套指标（Affiliation / VUS / R-AUC 等）
    • 异常分数时序图：X 轴样本序号 / Y 轴异常分数
      • 支持缩放、按步长平移、起止索引跳转
      • 异常点标红，连续异常区间以半透明色带框出
    • 阈值档位选择器（0.1% / 0.5% / 1% / … / 25%），切换时图与指标联动
  4. 部署与文档
    • 前端构建产物由后端托管，python app.py 单命令启动
    • README 使用说明（环境准备、启动、常见问题）
  5. 端到端验收：完整走通"选数据 → 训练 → 管理 → 检测 → 看结果"全链路

核对点

  • Lab 结果页的指标选择是否覆盖所需？阈值档位粒度是否需要调整？
  • 异常分数时序图的交互（缩放 / 平移 / 跳转 / 标红 / 区间带）是否符合预期？
  • 部署方式（单命令启动）与文档是否满足他人复现需求？
  • 整体是否满足"训练—管理—测试"完整闭环？

演示内容

"我的模型"选择模型 → 跳转 Lab → 选择数据集（演示通道数不匹配预警）→ 执行检测 → 结果页切换阈值档位，观察图表与指标联动 → 完整链路展示
